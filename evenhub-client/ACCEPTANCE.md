# Приёмка OcuClaw на Android, G2 и R1

Статус этой сборки — готова к запуску локального стенда. Результат испытаний
на устройствах заполняется отдельно. На VPS переходят после аппаратной приёмки.

## Подготовка

- Записать коммит и SHA-256 файла `.ehpk`, модель Android и версию ОС, версию
  приложения Even Realities, прошивки G2 и R1. Минимум для этой сборки — Even App 2.3.2.
- Подключить G2 и R1 в Even Realities. Начать с телефона без подключённых очков,
  затем подключить G2 и кольцо. Основные сценарии на очках выполнять кольцом.
- Для QR использовать аккаунт разработчика Even Hub. Если сканер не виден,
  войти тем же аккаунтом в веб-портал и перезапустить Even Realities.
  [Подготовка устройств](https://hub.evenrealities.com/docs/get-started/quickstart/hardware)

## 1. QR на устройствах с локальным стендом

Выполнить из корня репозитория. Подставить адрес Mac в Wi-Fi, к которому
подключён Android.

```sh
npm install
npm --prefix evenhub-client ci
npm --prefix evenhub-client run build
npm --prefix evenhub-client run test:device -- 192.168.8.217
```

Стенд выводит URL страницы, адрес WebSocket и одноразовый тестовый ключ.
Во втором терминале сгенерировать QR с URL из вывода.

```sh
cd evenhub-client
npx evenhub qr --url http://192.168.8.217:5180/
```

В Even Realities открыть Even Hub → сканер в разделе разработчика. Открыть
«Настройки» OcuClaw и ввести адрес с путём `/relay` и тестовый ключ.
HTTP/WS использовать только в локальной сети с этим тестовым ключом.
Если Android не загружает URL, проверить доступность страницы с телефона
и отсутствие изоляции клиентов Wi-Fi. [Локальный режим Even Hub](https://hub.evenrealities.com/docs/test/local-testing)

Стенд обслуживает один активный телефон. Он подставляет синтетические чаты,
три вопроса и результат. STT возвращает фиксированный текст, а команда `status`
показывает количество полученных байт PCM. Планирование и операции имитируются.
Стенд не подключается к Hermes и не исполняет команды или задачи.

| Действие в терминале стенда | Что проверяет |
| --- | --- |
| `seed` | Новый набор из трёх вопросов и одного результата. У объектов новые ID. |
| `resolve` | Закрытие вопросов из другого интерфейса. |
| `expire` | Истечение сроков при записи или на экране подтверждения. |
| `drop-answer`, `drop-message`, `drop-job` | Операция применяется, затем сокет закрывается до ответа. Вводить команду перед подтверждением на устройстве. |
| `fail-stt` | Следующее распознавание возвращает ошибку. |
| `status`, `quit` | Вызовы и ID операций без текста сообщений или аудио. Остановка стенда. |

### Сценарии на устройствах

| ID | Шаги | Критерий |
| --- | --- | --- |
| A1 | Открыть приложение без G2. Подключиться к стенду, открыть чат, набрать многострочный черновик и сменить экран. | Чаты и Входящие работают. При возврате черновик на месте, клавиатура оставляет поле ввода доступным. |
| A2 | В чате надиктовать короткую фразу микрофоном телефона. Затем подключить G2 и повторить, выбрав микрофон очков в настройках. | Стенд видит ненулевое число байт для обеих записей. Текст остаётся в редактируемом черновике до отправки. |
| A3 | В установленной сборке выбрать фото из галереи, сделать снимок, добавить небольшой документ. Отменить один выбор и удалить вложение из черновика. | Отмена сохраняет существующий черновик. Имена выбранных файлов видны до отправки. Повторить после отказа в доступе к микрофону, камере и альбому. |
| R1 | Подключить G2 после запуска телефона. Пройти меню свайпами, открыть вопрос касанием и вернуться двойным касанием. Проверить контекстное меню. | Один жест даёт одно действие. Нет зависших или смешанных кадров. На корневом экране beta-сборки двойное касание показывает системный диалог выхода. |
| R2 | Ответить на первый вопрос с выбором, затем пройти через «Следующий вопрос» к нескольким вариантам. Открыть полное описание разрешения и отменить. | Кириллица и варианты читаются. Подтверждение видно до отправки. Быстрое повторное касание не отправляет ответ. Запрошенное действие и область разрешения различимы. |
| R3 | Открыть запись на G2, применить `fail-stt`, завершить запись и повторить распознавание. Повторить с `expire` во время записи или подтверждения. | Оба STT-запроса содержат тот же объём PCM. Истёкший вопрос закрывается без вызова `inbox.answer`. |
| R4 | Открыть вопрос и результат с G2 на телефоне. Оставить вопрос на подтверждении и применить `resolve`. | Телефон открывает выбранный объект. Навигация на другом экране сохраняется. Закрытый запрос нельзя подтвердить. |
| N1 | Перед ответом применить `drop-answer`, перед сообщением — `drop-message`, перед сохранением новой задачи — `drop-job`. | После переподключения на подтверждении ответа появляется «Проверить отправку». Операции также доступны через «Нужна проверка» после возврата из подтверждения. В `status` одна мутация на исходный ID. |
| S1 | Создать задачу на телефоне и голосом на G2. Просмотреть даты, вернуться к черновику, затем явно подтвердить. | До подтверждения нет `automations.create`. Созданная задача появляется в расписании. Нативные даты, состояние и история проверяются в разделе 3. |

## 2. Установленная сборка и блокировка Android

Собрать пакет для точного WSS-адреса тестового стенда. Адрес должен быть
доступен Android с доверенным сертификатом. Локальный стенд может обслуживать
HTTPS/WSS через `OCUCLAW_QA_TLS_KEY` и `OCUCLAW_QA_TLS_CERT`. Использовать имя
из сертификата в адресе, даже если стенд слушает LAN IP. При необходимости
указать несколько WSS-адресов в одной команде упаковки.

```sh
cd evenhub-client
npm run pack -- wss://qa.example.test:5180/relay
shasum -a 256 ocuclaw-inbox.ehpk
```

Адрес в манифесте ограничивает доступ к указанным origin. Тестовый и будущий
адреса можно включить вместе, когда оба известны. Ключ вводится в приложении.
`--lan ws://...` создаёт отдельный `ocuclaw-inbox-qa.ehpk` для LAN; Android
может отклонить незашифрованный WebSocket в установленной сборке.

1. Загрузить `.ehpk` как private build через портал Even Hub и установить
   на телефон из **Me → Apps → Private builds**. Если версия уже загружалась,
   назначить следующую версию в `app.json` перед упаковкой. Проверить запуск,
   WSS-подключение и выдачу разрешений. [Private Testing](https://hub.evenrealities.com/docs/test/private-testing)
2. Для проверки блокировки установить ту же сборку в beta-канале под своим
   аккаунтом. Открыть вопрос на G2, заблокировать Android на пять минут.
   Отдельным прогоном вызвать `seed` с новым вопросом во время блокировки,
   проверить индикацию, навигацию кольцом и сверку очереди после разблокировки.
   Записать, что фактически работало при заблокированном Android.
   [Beta Testing](https://hub.evenrealities.com/docs/test/beta-testing)
3. Выключить и включить G2 во время активной сессии. Убедиться, что телефон
   сохраняет чат, а HUD возвращается на очках. Повторить без Wi-Fi и после
   возвращения связи. При проверке сохранения ключа перезапустить клиент сначала
   с выключенным сохранением, затем с включённым и после «Забыть».

Для каждого прогона записать `PASS / FAIL / BLOCKED`, ID сценария, версии
оборудования, режим Even Hub, сеть и наблюдение. При сбое сохранить время,
действие, текст ошибки и, если есть, ID операции. Ключи, записи и личные
данные в отчёт не включать. Повторная отправка, перепутанный адресат, отсутствие
подтверждения или срыв обязательного сценария с заблокированным Android
блокируют VPS-деплой.

## 3. Настоящий Hermes и последний шаг на VPS

1. До VPS повторить серверные тесты на изолированной Hermes 0.21.1.
   Ревизия и процедура в [Hermes Workspace integration candidate](../hermes-public/README.md).
   На отдельном тестовом Hermes с настроенными моделью и STT повторить A2,
   A3, N1 и S1. Проверить вопросы Desktop и клиента в обоих направлениях,
   поток чата после обрыва, правки расписания из другого интерфейса, запускаемую
   сессию, остановку отдельно от паузы и запуск при закрытом клиенте.
   Перезапустить тестовый Hermes и сверить пропуск, историю и результаты.
2. Только после аппаратного прогона сверить рабочий VPS в режиме чтения.
   Зафиксировать версии Hermes, OcuClaw и Desktop, origin релея, обслуживаемые
   профили, доступность STT и native Workspace. Сверить хеши исходников
   Hermes с матрицей совместимости и подтвердить маршрутизацию Desktop-вопроса
   к тому же работающему gateway. Подготовить резервную копию кода, настроек
   и SQLite/cron-состояния, записать исходные версии и порядок отката.
3. Последнее изменение — развернуть проверенную ветку и совместимый адаптер.
   Пройти короткий прогон на отдельной тестовой сессии. Проверить WSS, вопрос
   из Desktop, одну диктовку, ручной запуск и результат, затем совместимость
   прежнего клиента. При регрессии остановить тестовые запуски, вернуть прежний
   код и настройки, сверить состояние с резервной копией перед восстановлением БД.
